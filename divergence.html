Float Divergence

IEEE 754 does not guarantee bit-identical results across platforms, and NVIDIA’s own CUDA documentation says so. The records below show what that looks like in practice.

The Record

GPU FINDING: path-dependent and scheduling-dependent divergence

The same 1,000,000-element float32 corpus, run on a local NVIDIA RTX 3050 and two Google Colab Tesla T4 instances. Source code and compiler flags were identical, compiled independently on each machine.

The deterministic kernels produce bit-identical output on both GPU architectures. Changing a compiler flag on the same GPU changes the output. Atomic reduction is non-deterministic from run to run at this size, while tree reduction was deterministic in every current run. The fast and accurate rows compare __expf against expf, so they are not an isolated flush-to-zero toggle. These are expected, documented behaviors of compiler flags and thread scheduling. The point is that output depends on the build and the schedule, not on a defect in either GPU.

Full manifests and hash logs are in the GPU harness repo. A CPU result previously published from this harness was retracted on November 2, 2026 after a fault in the harness was found. See the correction notice in the repository.

What if my machines match?

          
If your hex view matches one of the results (A, B, or C) above, those machines behaved identically on this test. That does not prove your fleet is safe, and it does not mean the hardware is the same: Result C contains both an Intel and an AMD chip. This test does not isolate the cause. For path-dependent divergence at the binary level on GPUs (FMA versus non-FMA, fast-math versus accurate library, and atomic scheduling), run the GPU harness.

The Divergence Baseline

      
Everything else on this page is measured against this one number.

    

    

      
Before you run the script: Pick two machines that are actually different. An Intel laptop and an AMD cloud VM, or a local WSL2 instance and a Colab instance. If you run it on two identical work laptops, they will likely match, and you will miss the divergence.

    

    

      
The Test
prove_divergence.py prints the host CPU model and Python version, runs a sorting-then-summing experiment, and reports the sorted-sum with its hex view.

      
The Result
Five environments produced three different sums, spread across 1.25390625. An Intel Xeon and an AMD EPYC agree; two Intel Xeons disagree. The vendor on the chip does not predict the answer.

      
Not Claimed
The script does not isolate the cause. CPU instruction set, library build and interpreter version are all uncontrolled across these runs (Python 3.12.3, 3.13.7 and 3.13.16 appear). Results A and C share Python 3.13.16 and still differ, so the interpreter alone does not explain the spread. The script prints the Python version so you can compare like with like. Run it on your own fleet; that is the test that matters.
